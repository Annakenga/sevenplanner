# План создания MVP Seven

## Цель MVP

Создать удобный планер, которым можно пользоваться без регистрации сразу после открытия сайта. Все содержательные данные остаются на устройстве пользователя.

## Этап 1. Зафиксировать продукт

- Определить главный сценарий и состав первого экрана.
- Утвердить обязательные функции MVP.
- Собрать визуальные ориентиры и правила интерфейса в `resources`.
- Зафиксировать, какие браузеры и размеры экранов поддерживаем в первой версии.

Результат: короткая спецификация MVP и понятная структура экранов.

## Этап 2. Подготовить фундамент

- Настроить статическое веб-приложение для GitHub Pages.
- Заложить структуру данных и версионирование IndexedDB.
- Добавить единый слой работы с локальными данными, чтобы будущие изменения не ломали сохранённые задачи.
- Настроить базовые проверки качества и сборку проекта.

Результат: пустая, но технически готовая оболочка Seven.

## Этап 3. Реализовать основной сценарий

- Создание, редактирование, выполнение и удаление задач.
- Отображение задач в выбранной структуре планера.
- Сохранение всех изменений в IndexedDB.
- Понятные пустые состояния и подтверждения опасных действий.
- Удобство с клавиатуры, мыши и сенсорного экрана.

Результат: первая действительно полезная версия планера.

## Этап 4. Защитить локальные данные

- Объяснить пользователю, где хранятся данные и когда они могут быть потеряны.
- Добавить экспорт резервной копии в файл.
- Добавить восстановление из резервной копии с проверкой формата.
- Проверить обновление структуры базы без потери существующих данных.

Результат: пользователь может самостоятельно перенести или восстановить свой планер.

## Этап 5. Доработать качество MVP

- Адаптировать интерфейс для компьютера и телефона.
- Проверить основные сценарии в актуальных браузерах.
- Добавить обработку ошибок и недоступности IndexedDB.
- Проверить скорость загрузки, доступность и приватность.

Результат: стабильный кандидат на публикацию.

## Этап 6. Опубликовать

- Создать репозиторий GitHub и загрузить проект.
- Настроить автоматическую публикацию на GitHub Pages.
- Проверить работу по адресу GitHub Pages.
- Купить домен в Timeweb, указать его в настройках GitHub Pages и добавить DNS-записи.
- Включить HTTPS и проверить основной домен и `www`.

Результат: Seven доступен по собственному домену.

## Этап 7. Подключить безопасную аналитику

- Выбрать решение с минимальным объёмом собираемых данных.
- Отслеживать только посещения, возвраты и заранее согласованные обезличенные события функций.
- Не отправлять названия, тексты, описания, даты задач и содержимое резервных копий.
- Описать аналитику в политике приватности и проверить реальные сетевые запросы.

Результат: понятная статистика использования без доступа к содержимому планера.

## Критерии готовности MVP

- Планером можно пользоваться без аккаунта.
- После перезагрузки страницы данные остаются на месте.
- Основной сценарий работает на компьютере и телефоне.
- Пользователь может создать резервную копию и восстановить её.
- Сборка публикуется на GitHub Pages без серверной части.
- Тексты и другие содержательные данные пользователя не покидают его браузер.
